# Neskai — подробный аудит приложения

Дата аудита: 11 мая 2026
Область: frontend (Next.js App Router), API routes, Supabase integration, миграции БД, UX совместного чтения

## 1) Краткое резюме

Проект уже реализует рабочее ядро продукта: авторизация через Google, библиотека, загрузка EPUB/PDF с компрессией, индивидуальное и совместное чтение, выделения, треды и реакции, синхронизация позиции и курсора через Realtime, PWA-сборка.

Текущее состояние можно оценить как: MVP+ с сильным продуктовым фокусом, но с заметным потенциалом по надежности, тестированию, операционной зрелости и частичной унификации UX/API.

## 2) Текущая структура приложения

### 2.1 Структура модулей

- UI shell и страницы:
- главная, библиотека, добавление книги, ридер книги, комната совместного чтения, профиль, инвайт, логин
- Компоненты:
- каталог книг, presence на главной, верхние действия, мобильный таббар, shared reader и его UI-слой
- API routes:
- auth/google, auth/callback, signout, annotations, threads, messages, reactions, compress-pdf
- Инфраструктура:
- Supabase browser/server clients, route auth helper, origin resolver, local session storage
- База данных:
- SQL-миграция collaborative annotations + threads + reactions + RLS + индексы
- PWA:
- next-pwa, service worker в public

### 2.2 Основной пользовательский флоу

- Логин через Google OAuth
- Переход в библиотеку
- Добавление EPUB/PDF
- Открытие ридера
- Выделение текста, реакции, мысли/треды
- Приглашение в reading room
- Совместное чтение с синхронизацией страницы и курсоров
- Сохранение последней сессии в localStorage

## 3) Что реализовано

### 3.1 Авторизация и сессии

- Реализован Google OAuth через Supabase (PKCE).
- Реализован callback-обмен code -> session на сервере.
- Реализован signout route с server-side signOut.
- Реализована проверка пользователя на серверных страницах (например, профиль).

### 3.2 Библиотека и загрузка книг

- Список книг с realtime-обновлением через postgres_changes.
- Удаление книги из библиотеки.
- Форма добавления книги с метаданными.
- Поддержка EPUB и PDF.
- Лимит на размер файла 50 MB с попыткой компрессии.
- EPUB-компрессия на клиенте через JSZip.
- PDF-компрессия через серверный route и Ghostscript.

### 3.3 Чтение и аннотации

- SharedReader с режимами paginated/scrolled.
- Выбор темы ридера и размера шрифта.
- Выделения (цвет и weight normal/bold).
- Отображение реакций поверх контента EPUB.
- Отрисовка удаленного курсора в reading room.
- Стабилизирована логика ридера при выделении (устранено повторное пересоздание на ререндерах).

### 3.4 Совместное чтение

- Presence списка участников.
- Инвайты через broadcast-channel.
- Синхронизация позиции чтения (cfi).
- Синхронизация новых выделений.
- Синхронизация тред-сообщений.
- Синхронизация реакций на аннотации.
- Сохранение/восстановление последней сессии чтения.

### 3.5 API и БД

- CRUD-минимум для annotations/threads/messages/reactions.
- Валидации payload в route handlers.
- Ограничение реакций: ровно одна цель (annotation или message).
- Индексы и уникальные индексы на реакции.
- Базовые RLS политики для auth-пользователей.

### 3.6 Платформенные возможности

- Next.js App Router (client + server pages).
- PWA подключение (service worker, manifest).
- SEO metadata/viewport настроены.

## 4) Что не реализовано или реализовано частично

### 4.1 Тесты и контроль качества

- Нет unit-тестов.
- Нет integration/e2e тестов.
- Нет контрактных тестов API.
- Нет snapshot/regression тестов для сложного reader UX.

### 4.2 Надежность и восстановление

- Нет централизованного Error Boundary (app-level error.tsx).
- Нет loading.tsx экранов для маршрутов App Router.
- Нет retry/backoff слоя для сетевых операций fetch/supabase.
- Нет очереди офлайн-действий для совместного режима.

### 4.3 Безопасность и доступ

- Нет middleware для централизованной защиты закрытых роутов.
- Есть дублирование входа в OAuth: клиентский логин и отдельный auth/google route (функционально пересекаются).
- Не видно строгой валидации форматов file_url/cover_url на стороне API.

### 4.4 Продуктовые пробелы

- Нет явной пагинации списка книг.
- Нет поиска/фильтров по библиотеке.
- Нет UX управления реакциями на сообщения (поддержка message_id в БД/API есть, но фича в UI не раскрыта полноценно).
- Нет истории аннотаций/мыслей отдельным экраном.
- Нет явной аналитики активности чтения.

### 4.5 Операционная зрелость

- Нет мониторинга ошибок (например, Sentry).
- Нет технической документации архитектуры в репозитории.
- Нет CI-пайплайна, который гоняет тесты/линт/типизацию на PR.

## 5) Что можно улучшить (приоритизировано)

### 5.1 Высокий приоритет

- Добавить app-level error.tsx + segment-level error boundaries.
- Добавить loading.tsx для ключевых экранов (books, readers, reading-room).
- Добавить интеграционные тесты critical path:
- логин -> библиотека -> открыть книгу -> выделить -> отправить мысль -> получить реакцию второго пользователя.
- Ввести единый auth flow (оставить один источник правды: либо route auth/google, либо чисто клиентский OAuth старт).
- Добавить централизованный обработчик ошибок API с унифицированным форматом ответов.

### 5.2 Средний приоритет

- Выделить shared data layer (hooks/services) для Supabase/fetch, чтобы снизить связность страниц.
- Добавить optimistic UI + rollback для create highlight / reaction / message.
- Добавить debounce/throttle и soft-reconnect стратегии для realtime каналов.
- Добавить серверную валидацию mime/type/extension и санитаризацию пользовательских полей.
- Добавить базовый rate-limit на write API endpoints.

### 5.3 Низкий приоритет

- Вынести product-копирайтинг и локализацию в i18n-слой.
- Улучшить consistency текста интерфейса (RU/EN смешение).
- Добавить расширенную телеметрию UX (время чтения, глубина, retention).

## 6) Что уже хорошо работает (сильные стороны)

- Четкое продуктовое ядро: совместное чтение реализовано end-to-end.
- Современный стек: Next 16 + React 19 + Supabase Realtime + App Router.
- Хорошая композиция UI-компонентов в Reader экосистеме.
- Реальная практическая ценность: выделения, реакции, треды, presence.
- Наличие компрессии больших файлов и ограничений по размеру.
- Наличие SQL-миграции и индексов для ключевых сущностей.
- Наличие RLS-основания (пусть и с потенциалом усиления).
- Плавная UI-анимация и аккуратный визуальный язык.
- Состояние сборки стабильное, TypeScript/Next build проходят.

## 7) Технические риски (точечно)

- Зависимость PDF-компрессии от Ghostscript на сервере (операционный риск окружения).
- Несколько lockfile в workspace (предупреждение Next про root inference).
- Сложность SharedReader высокая, есть риск будущих регрессий без тестов.
- Realtime-логика требует регулярной ревизии утечек подписок/каналов.

## 8) Рекомендуемый план на 2 итерации

### Итерация 1 (стабильность)

- Error/loading boundaries.
- Unified auth flow.
- API error contract.
- Integration smoke tests для critical reading path.

### Итерация 2 (масштабирование)

- Data/service слой и декомпозиция логики reading-room.
- Расширение UX (поиск по библиотеке, message reactions UI, history screen).
- Наблюдаемость (Sentry + базовые продуктовые события).

## 9) Итоговая оценка

- Архитектурная зрелость: средняя.
- Продуктовая готовность: выше средней (рабочее collaborative MVP).
- Техническая устойчивость: средняя, усилить тестами и обработкой ошибок.
- Потенциал роста: высокий.
